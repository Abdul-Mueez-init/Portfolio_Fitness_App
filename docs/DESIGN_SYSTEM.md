# FitForge AI Design System

Version: 1.0

---

# Purpose

This document defines the visual language of FitForge AI.

Every screen should look like it belongs to the same application.

Consistency is more important than creativity.

---

# Design Philosophy

The UI should feel:

• Premium
• Modern
• Minimal
• Athletic
• AI-powered
• Clean
• Fast

Every screen should communicate confidence.

---

# Inspiration

Applications that inspire this project:

- Nike Training Club
- Apple Fitness
- Strong
- MyFitnessPal
- Whoop
- Notion
- Linear

We are inspired by them, not copying them.

# Color Palette

## Primary

Electric Blue

Used for:

- Primary buttons
- Highlights
- Active icons
- Progress

---

## Background

Pure Black

Surface Black

Card Black

Different shades only.

Never flat grey.

---

## Text

Primary White

Secondary Grey

Disabled Grey

Success Green

Warning Orange

Error Red

---

# Typography

All text styles live inside:

AppTypography

Never create TextStyle inline.

## Heading

Large

Bold

Home

Workout

Coach

## Title

Semi Bold

Cards

Dialogs

Sections

## Body

Regular

Easy to read

## Caption

Smaller

Descriptions

---

# Spacing

Use spacing constants.

Never hardcode spacing.

Example:

xs

sm

md

lg

xl

2xl

---

# Border Radius

Consistent everywhere.

Small

Medium

Large

Extra Large

Buttons and cards should match.

---

# Elevation

Minimal.

Prefer shadows over elevation.

Avoid Material default appearance.

---

# Cards

Cards should:

Have breathing room

Rounded corners

Subtle border

Soft shadow

Padding on all sides

---

# Buttons

Primary Button

Filled

Accent color

Rounded

Medium height

Secondary Button

Outlined

Neutral color

Text Button

Minimal

No background

---

# Input Fields

Rounded

Filled background

Clear placeholder

Visible focus state

Proper error state

---

# Icons

Use one icon family only.

Consistent sizing.

Do not mix icon packs.

---

# Animations

Animations should feel natural.

Preferred duration:

150–300ms

Avoid flashy animations.

---

# Images

High quality only.

No pixelated assets.

Maintain aspect ratios.

---

# Component Rules

If reused:

Extract into shared widgets.

Never duplicate components.

---

# Accessibility

Readable contrast.

Large tap targets.

Support text scaling.

Avoid tiny fonts.

---

# Empty States

Every empty screen should include:

Illustration

Helpful text

Call to action

---

# Loading States

Prefer Skeleton UI.

Avoid infinite spinners.

---

# Error States

Friendly.

Actionable.

Always provide retry.

---

# Success States

Use subtle animations.

Positive messaging.

---

# Design Principle

Every screen should answer:

What is important?

What should the user do next?

Nothing else should compete for attention.
